# Interactive user pass — September 20, 2026

Used the real Web UI in a headed browser and the real TUI through an interactive terminal. Prompts ran against local models, not prerecorded responses. Separate `cg-next-*-pass-20260920` temporary profiles kept test sessions/settings out of the normal profile. No paid provider calls or project-editing model prompts were used.

## Found and fixed

- TUI Ctrl+C always exited. It now copies a composer selection through the OS clipboard, stops an active turn, clears a draft, then quits only from an empty idle composer. The selected-text path was exercised against the Windows clipboard.
- Mouse clicks were discarded. The TUI now starts with mouse controls enabled and has clickable `+`, model, settings, sessions and usage controls; dialog rows are clickable too. Long model dialogs now reserve the composer/footer in an 80x24 terminal.
- Settings existed only as media-generation rows. Both frontends now have general settings panels for theme, thinking, reasoning effort and relevant controls; the Web UI also has persistent sidebar/activity toggles.
- The two slash catalogs could drift and original-CG aliases disappeared. Both surfaces now consume the shared catalog and aliases. Commands not implemented yet are visible and return a local “not wired yet” explanation instead of reaching a model.
- Web Help dumped the complete command/skill catalog into the conversation. It is now a searchable command-browser dialog, including aliases and pending commands.
- The clickable file mentioner ranked Playwright snapshots, isolated output profiles and the corrupted recovery mirror as project files. Generated/recovered directories are now excluded from project search.
- Session usage now distinguishes “no response yet,” “provider did not report tokens/cost,” priced estimates and mixed unpriced usage. Estimated context remains visible when token billing data is unavailable and survives reopening a session.
- Local-chat context was overstated because the meter counted the full coding-agent prompt even though lean local chat does not send it. Metering and the compaction threshold now use the exact lean message set; the one-line 2K-context smoke session moved from an incorrect 21% to ~2%.
- Web `/clear` was advertised but returned “unknown command”; it now shares the new-conversation action.
- Web slash controls were blocked while a turn ran. Approval/help/status/theme/thinking/effort controls now execute immediately. Other commands/prompts queue.
- The browser approval dropdown changed only the next request. A dedicated mode endpoint now updates the current conversation and re-evaluates waiting approvals while retaining ask/deny/plan restrictions.
- New-session, resume and model clicks could replace visible state while the old stream continued. These actions now defer until the active turn ends. A newer queued action explicitly replaces the previous one.
- Shift-Tab inside the TUI approval picker changed the actual permission mode without updating the marker. The picker now refreshes and selects the actual mode.
- A new unsent TUI draft disappeared when an earlier queued follow-up started. Plain queued prompts now preserve the newer composer contents.
- Local servers could answer with a model different from the UI label. Observed another Bonsai server on port 8788 while the UI still said Qwen. Local inference now verifies the `/models` identity and refuses a mismatch. Tests moved to port 18991; the other server was not stopped or modified.
- Offline local-server failures were generic. They now identify the endpoint and tell the user to start the server.
- Provider output-token exhaustion looked like a completed answer. Both surfaces now warn, the stored answer carries an unfinished marker, and truncated tool calls are not executed.
- Qwen's zero-reasoning-budget configuration exposed raw `</think>` text. Added optional local `enable_thinking` template configuration; disabling it removed the marker in a repeated browser test without filtering legitimate model text.

## Local model evidence and limits

Official Qwen3 0.6B Q8_0 was checksum-verified. On the dedicated CPU server it answered `17 × 23 = 391`, produced a story, and streamed programming text in both interfaces. The answers were too shallow to call it a validated coding agent. Local tools remain opt-in and were not certified by these chat tests.

Initial server logs measured roughly 31–60 generated tokens/second for 0.6B on four CPU threads. This is a smoke-test observation, not a controlled benchmark. Responses produced after the initial port was taken by Bonsai are excluded from Qwen quality/performance conclusions.

The GPU had only about 180 MB free at the start, so no existing GPU workload was displaced. Model downloads live outside the repositories under `C:\Users\shawn\.local\share\cg-next\models`.

Qwen3 1.7B Q8_0 also finished downloading after resuming a failed transfer. SHA-256 matched the official repository: `061b54daade076b5d3362dac252678d17da8c68f07560be70818cace6590cb1a`. It was tested sequentially after stopping the 0.6B server, using 2048 context tokens, four CPU threads and a 256-token output budget. In the browser it returned an order-preserving string-deduplication function using a Set and an example; the TUI also streamed a coding response while its approval picker and Shift-Tab remained usable. One browser response logged about 22 generated tokens/second. This remains chat/code-generation smoke testing, not autonomous tool-use validation.

Final verification: `bun typecheck` clean, `bun run test` 624 pass / 0 fail, plus the expanded real-PTY regression (live approvals, Shift-Tab, slash commands during streaming, queued-draft preservation and queued clear).
