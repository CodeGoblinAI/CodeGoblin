## Reproducible findings — initial pass, fixed above

### 1. P1 — TUI Ctrl+C leaves a stopped turn waiting on approval

1. Ask Codex to use `write_file` in Ask mode.
2. Wait for the Allow once / Allow for this session / Reject question.
3. Open `/usage`, then press Ctrl+C.

Observed: status changes to `stopped`, but the pending approval and streaming-state
footer remain. The turn does not release itself. Enter first dismisses Usage; answering
the approval afterward finally releases the stopped turn. The target file was **not**
written. The problem is a blocked cancellation/false stopped state, not an observed
post-cancel write.

Code pointer: `src/tui/app.ts:2395` aborts the turn but does not settle `pending` or
`waitingAsks`. The adjacent Ctrl+S interrupt path already rejects these questions.
Add a real interaction-level regression for cancellation while consent is awaited;
the existing Ctrl+C action-selection unit test alone passes.

### 2. P2 — Web stopped approvals remain clickable and report false success

Stop a turn while a `write_file` approval is visible. The turn becomes Idle and says
`_stopped_`, but all approval buttons remain enabled. Clicking Allow once changes the
old row to `allow once`, although the server has no pending request and no file is
written. The UI updates the row before checking the response.

Code pointers: `src/web/app.js` permissionPrompt/answer and stopTurn/turn completion;
`src/web/serve.ts:584` correctly refuses stale permission IDs. Cancel/expire the row
visibly and check `response.ok` before showing an accepted decision.

### 3. P2 — Dynamic Codex model launch silently selects the wrong provider

Launching the actual TUI with `--model codex/gpt-5.6-luna` selected DeepSeek instead.
The same Codex model can be selected with `/model codex/gpt-5.6-luna` after the
official catalog has loaded. No prompt was submitted to the unintended provider.

Code pointer: `src/tui/app.ts:121` resolves the launch selection before the async
official CLI model discovery and defaults on failure. Preserve the requested model
until discovery, or fail visibly; do not silently route an explicit model choice to
another provider. `--model codex` remains a usable launch workaround.

### 4. P2 — Web model picker is mouse-only

Open the model menu and attempt Down/Enter, including with the list itself focused.
No model is selected. Tab does not provide usable option navigation. Options are
non-focusable divs, and the menu has only click/Escape behavior.

Code pointers: `src/web/app.js:19` renderModelMenu and button handlers below it. Add
roving/active-descendant listbox keyboard behavior, selected state and focus return.
The slash command and file palettes already provide a keyboard-friendly reference.

### 5. P2 — TUI project-file list becomes stale until restart

Start the TUI in an empty disposable workspace. Create a file in that workspace
through the Web agent, then use TUI + → Mention a project file. No file choices
appear. Restart the TUI: the two workspace files appear and can be completed.

Code pointer: `src/tui/app.ts:2320` refreshFileCache is only invoked at startup.
Refresh on mention/picker use or after changes, with bounded caching.

### 6. P2 — Web `/export <path>` silently ignores the path

`/export exported-user-pass.md` wrote `codegoblin-user-pass-october-4.md` in the
workspace instead. The requested file was not created. The shared command Help
advertises path arguments, and the TUI passes them to the shared exporter.

Code pointers: `src/web/app.js:1130` posts only sessionId;
`src/web/serve.ts:366` omits the exporter target. Pass the explicit target through,
or clearly refuse unsupported arguments rather than silently dropping them.

### 7. P2 — Web file-picker completion can leave Send disabled

From an empty composer, + → Mention a project file → Down/Tab inserts
`@user-test.txt`, but Send remains disabled. Typing one more character enables it.
Keyboard submission was not tested here because that would send another model turn.

Code pointer: `src/web/app.js:2023` choose assigns input.value without refreshing
the Send button state; that state is otherwise updated by the input event handler.
