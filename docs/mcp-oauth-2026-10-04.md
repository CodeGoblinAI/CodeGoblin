# Hosted MCP OAuth — independent concern branch

`codex/mcp-oauth`, based on `codex/phase2-hardening` (`6607a15`); not merged, no PR, no dependency additions.

## Built

Hand-rolled HTTPS remote OAuth: protected-resource discovery from a Bearer challenge or path/root well-known metadata; OAuth/OIDC issuer discovery; validated issuer, S256 PKCE, unpredictable state, exact loopback Host/path, optional authorization-response issuer check, resource parameters in authorization/code/refresh requests, public dynamic registration or configured `oauth.clientId`, and bounded single-flight token refresh. Tokens only reach the configured resource's HTTP Authorization header. No configured MCP headers or cookies reach discovery/registration/token endpoints. Redirects, private-address DNS results, issuer/resource mismatches and oversized JSON fail closed.

401 and challenged insufficient-scope 403 become a visible authorization-required status. Expired/invalid auth removes tools until reauthorized; tool calls are never automatically replayed. A successful owned login reconnects and lists tools through the existing permission-gated MCP path. `/mcp` now has Web/TUI sign-in controls, warnings, manual status checks and cancellation. Automatic connection/model activity cannot start registration or account authorization.

Credentials are stored atomically per exact server endpoint under this profile's `data/mcp-oauth/`, outside session/transcript. POSIX mode 0600; Windows inherits directory ACLs (mode alone is not encryption or an owner-only ACL). Do not commit/share that profile. Cancel stops an unfinished attempt, not a grant/token already completed; revoke grants at the provider.

Supported scope: public PKCE clients via DCR/pre-registration. No hosted Client ID Metadata Document, confidential client-secret auth, legacy SSE, automated revocation UI, or transparent step-up tool replay. OAuth resource URLs must be HTTPS without queries. Discovery metadata stays on the configured origin; authorization servers may be separate public HTTPS origins. DNS is checked but not socket-pinned against rebinding; a future transport hardening review should consider pinning. Servers requiring a fixed pre-registered callback port need additional configuration support.

## Real Notion handoff

Official [Notion endpoint](https://developers.notion.com/guides/mcp/get-started-with-mcp) `https://mcp.notion.com/mcp` returned its protected-resource challenge and valid S256 authorization metadata. Actual Web `/mcp` → Sign in → Start completed public registration (client name **CG-Next MCP**), then its link reached `https://app.notion.com/login`, “Log in to your Notion account.” **Stopped before entering credentials or granting workspace access**, as requested. Closing cancelled the pending callback; no Notion token was stored and no workspace tool was called. The TUI warning/copy/check/cancel flow was exercised at 80×24. A public OAuth client registration is not a workspace grant.

The Web popup fit 390×844 (356px wide). Fixture tests used real local HTTP and callback servers behind a test-only injected network; no account allowance or paid inference. Tests cover scopes/OIDC, PKCE/resource, wrong state/origin/issuer, decline/cancel, bounds/redirect/private-network refusal, authenticated MCP handshake, expired-token refresh and a 401 tool call without retry. Full suite: 698 tests. Typecheck, Web JS syntax and diff whitespace checks clean.

The implementation follows the [MCP authorization protocol](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization); do not claim support for every optional registration mechanism.
